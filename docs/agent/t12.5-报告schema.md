# T12.5 守恒审计报告 schema（v1）与三态声明

> 任务：T12.5「schema 报告与回填」（docs/agent/重构任务清单.md T12.5 节，:212-226）。
> 本文件是守恒审计机器报告的版本化 schema 文档，同时是 T12.5 三态声明的现行记录。
> 实现：`src/main/kotlin/io/alexjoest/stackupup/audit/ConservationReportWriter.kt`，
> 事件模型 `ConservationEvent`（守恒公式 `storedDelta + remainderCount == offered`，T12.3），
> 关闭态开关单次读取（T12.4，`ConservationAuditor`）。
> 回填目标：`docs/agent/t2a-容量站点登记表.md` 与覆盖面决策记录
> （`docs/agent/compatibility-decision-record.md`）。
> 本文件只定义报告与状态，不定义生产容量规则，也不替代 T2a 的准入规则。

## 1. 事件报告（JSONL）

- 默认文件：`run/logs/stackupup-conservation.jsonl`（相对于 Gradle 运行目录，即项目根）。
- 路径可用系统属性 `stackupup.audit.conservation.report` 覆盖；该属性在
  `ConservationReportWriter` 类加载时单次读取，运行期不再读取（与 T12.4 单次读取门同构，
  由 `ConservationAuditorBytecodeTest` 结构检查）。
- 追加写：每条事件一行 JSON 对象 + 换行；只追加、不覆盖、不重排，同一次运行的写入顺序即事件发生顺序。
- 关闭态（默认，未设置 `stackupup.audit.conservation=true`）：不创建文件、不产生任何事件与 I/O。

### 1.1 字段（schemaVersion = 1）

每条记录必须且只含下列 11 个字段，不得缺失、不得改名、不得改变类型；增删字段必须 bump
`schemaVersion` 并在本文件登记。

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `schemaVersion` | int | schema 版本，当前恒为 1 |
| `callSite` | string | 调用点标识，如 `DevAutomationServerDriver#probeTarget`、`Ae2ItemHandlerInsertLimiter#insertCapped` |
| `handlerClassName` | string | 目标 `IItemHandler` 的实际类名（真实写入面，用于定位） |
| `slot` | int | 投喂槽位 |
| `simulate` | boolean | 是否 simulate 投喂；true 表示本次未改变状态 |
| `offered` | int | 本次投喂数量 |
| `before` | int | 投喂前槽内数量 |
| `after` | int | 投喂后槽内数量 |
| `storedDelta` | int | 落库增量 = `after - before`（显式落盘，解析方无需重算） |
| `remainderCount` | int | 投喂返回的余量数量 |
| `balanced` | boolean | 守恒判定：(storedDelta + remainderCount) == offered（显式落盘） |

示例（单行实际形态）：

```json
{"schemaVersion":1,"callSite":"DevAutomationServerDriver#probeTarget","handlerClassName":"net.minecraftforge.items.ItemStackHandler","slot":0,"simulate":false,"offered":128,"before":0,"after":128,"storedDelta":128,"remainderCount":0,"balanced":true}
```

### 1.2 语义与红线

- **只写原始事件**：审计开启时每条事件都写一行，不丢弃平衡事件、不丢弃 simulate 事件；
  任何人工摘要不得替代原始事件行。
- **simulate 不算守恒证据**：simulate=true 的事件同样按公式给出 `balanced` 值并落盘，
  但汇总中不计入 `unbalancedRealEvents`，也不得当作真实写入守恒证据（模拟不改变状态）。
- **报告不推断源码行为**：只有运行时事件、没有对应写入路径源码（含第三方无源码）时，
  一律保持 `无源码不可判定`，不得用报告数值反推源码语义。
- **告警不自动变补丁**：报告只观察与报告；本任务不含任何把告警变成补丁的逻辑。
- **不改第三方 jar**：报告器不触碰、不生成、不改写任何模组 jar。

## 2. 汇总报告（JSON）

- 默认文件：与事件报告同目录、同名派生 `stackupup-conservation-summary.json`
  （事件文件 basename 去 `.jsonl` 后缀 + `-summary.json`）。
- 每次事件写入后增量重写汇总文件，始终反映截至当前已写入的全部事件；
  汇总文件很小（按 类×调用点 聚合，条目数有界），且审计默认关闭，不影响常规运行。

```json
{"schemaVersion":1,"summaryKind":"conservation-unbalanced-summary","totalEvents":5,"simulateEvents":1,"unbalancedRealEvents":2,"unbalanced":[{"handlerClassName":"example.TruncatingHandler","callSite":"ConservationReportWriterTest","eventCount":2}]}
```

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `schemaVersion` | int | 与事件报告一致的 schema 版本（当前 1） |
| `summaryKind` | string | 固定 `conservation-unbalanced-summary` |
| `totalEvents` | int | 已写入事件总数 |
| `simulateEvents` | int | simulate=true 事件数（不参与不平衡判定） |
| `unbalancedRealEvents` | int | simulate=false 且 balanced=false 的事件数 |
| `unbalanced` | array | 不平衡条目：`handlerClassName`、`callSite`、`eventCount`；按 handlerClassName、callSite 排序，条目可逐条回到 JSONL 原始事件 |

## 3. 三态声明（当前状态）

T12.5 必须显式区分三种状态（重构任务清单.md:214-217）：

| 状态 | 判定 | 当前 |
| --- | --- | --- |
| 1 报告未完成 | 报告未生成、不可解析或缺少关键事件/字段 | 否 |
| 2 报告完成但回填未闭合 | 报告可解析且可追溯，但 T2 登记表或覆盖面决策记录未逐条回填闭合 | **是（当前，2026-08-08）** |
| 3 报告/关闭态门/回填证据均完成 | 报告可解析，T12.4 关闭态门通过，且 T2 登记表与覆盖面决策记录回填证据逐条完成 | 否 |

当前声明：报告生成能力已落地（schema v1：JSONL 事件 + 汇总；守恒 stub 与截断 stub 均生成可解析
JSONL，字段齐全，不平衡条目可回到调用点与 handler 类名；由 `ConservationReportWriterTest` 行为验证，
`ConservationAuditorBytecodeTest` 结构检查覆盖关闭态单次读取门）。T2 登记表
（`docs/agent/t2a-容量站点登记表.md`）与覆盖面决策记录的运行时回填尚未逐条闭合，
因此状态为**第二种**。**T13 保持锁定**；进入第三种状态需要：完整矩阵运行（`runServerAutoTestMatrix`）
生成可解析报告、T12.4 关闭态门通过、登记表每条回填引用原始事件行号，且无源码项保持 `无源码不可判定`。

## 4. 验证方式

- 行为测试：`ConservationReportWriterTest`（守恒/截断 stub → 可解析 JSONL、schema 字段齐全、
  不平衡可回溯、simulate 排除、汇总文件）；`ConservationAuditorTest` 与
  `Ae2ItemHandlerInsertLimiterConservationAuditTest` 覆盖审计器→报告器接线（报告文件重定向到临时目录）。
- 结构检查：`ConservationAuditorBytecodeTest`（报告路径属性仅初始化时单次读取，`write()` 不读配置）。
- 运行验证：`./gradlew runServerAutoTestMatrix` 后解析 `run/logs/stackupup-conservation.jsonl`
  （每行 11 字段齐全）与 `stackupup-conservation-summary.json`（不平衡类与调用点列表）。
- 停止条件：报告不可机器解析、缺少 `simulate` 或关键数值、同一次运行无法重现事件、
  或回填把 `无源码不可判定` 改成推测时停止（重构任务清单.md:224）。
