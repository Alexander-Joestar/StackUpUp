## 2. 失败诊断现状（任务第 2 项）
### 2.1 核心注入是否 fail-fast —— **现状：否**（命中 T14.5 停止条件）
字节码证据（mixinbooter-10.7.jar 内嵌 org/spongepowered/asm/*，2025-01-08 构建，运行日志确认运行时唯一 Mixin 核心）：
- `InjectionInfo.<init>`：`requiredCallbackCount=0`（putfield offset 75-76）、`expectedCallbackCount=1`（offset 70-71）、`maxCallbackCount=Integer.MAX_VALUE`（offset 79-82）。
- `InjectionInfo.parseRequirements`：注解无 `require`（或 ≤ -1）且 group 为 default → `requiredCallbackCount = MixinTargetContext.getDefaultRequiredInjections()` → `MixinConfig.getDefaultRequiredInjections()` → **`injectorOptions.defaultRequireValue` = 0**（`MixinConfig$InjectorOptions.<init>` iconst_0 putfield，无其它写点，也无 "injectors"/"defaultRequire" JSON 键）→ **配置级 `required=true` 不抬高注入默认值**。
- `InjectionInfo.validate`：`injectedCallbackCount < requiredCallbackCount`（0<0 恒假）→ 缺失注入点**零日志、零异常**；仅 `require>0` 抛 `InjectionError("Critical injection failure: ...")`。
- `MixinInfo.handleTargetError`：仅 `strict`（mixin.debug.strict / config strict）→ error+throw InvalidMixinException；非 strict：soft=false → WARN `@Mixin target %s was not found %s`；soft=true 且非 verbose → DEBUG（默认不可见）。
- `MixinInfo.readTargetClasses`：目标类缺失 → `isVirtual()`（@Pseudo）→ DEBUG `Skipping virtual target {} for {}`；非 virtual → handleTargetError(soft=false) → WARN，**不崩溃**。
- `MixinConfig` 崩溃路径（required 配置）：minVersion/requiredFeatures 不满足 → WARN + `MixinInitialisationError("Required mixin config ... requires ...")`（字节码确认；early.json:5-6 minVersion 0.8 满足，当前不触发）。
推论：early 核心 **26 处**无显式 require 的注入点（early 27 处注入注解行减 Q-REQ0-01；**原文写 27 处，与自身算术矛盾，2026-09 计数 lane 修正**）与 Q-REQ0-01 一样在注入点层面**静默失效**；核心 fail-fast 仅剩三条窄路径（版本不满足 / require>0 / target 过早加载），均未在本项目配置中启用。**违反 T14.5 禁止项「不得用 require=0、required=false 或 @Pseudo 隐藏核心目标缺失」的意图面**（early 未显式声明 require=1）。

## 3. 目标缺失日志/机器报告契约建议（只建议，不实施）
1. **分层声明**：early = core 层（装载必须 fail-fast）；late 16 个 = optional 层（允许缺失但必须有日志+机器报告；当前 late 为 16 个，StackUpUpMixinConnector.kt:220-239）。
