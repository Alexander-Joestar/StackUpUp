## 4. 快照与同步边界
- 单进程：RuleRuntime.replaceRuntime 一次 AtomicReference 替换，整体刷新 StackLimitService；失败路径保持旧快照；快照缺口：无 content hash、来源清单、协议 schema。跨进程：当前无任何规则同步包通道；联机两侧各自本地加载，一致性无校验、无运行证据。
- 目标边界（后续准入规格）：client hello(capabilities, protocol, codec) → server accept/reject → server 发送完整快照(version, hash, rules, overrides, cap) → client 校验并原子安装 → update(完整快照) → ACK。禁止：客户端本地 .su/旧缓存覆盖远端快照；只同步主表遗漏 override；以「magic byte 能读回来」替代端到端验证；包能传大数量当作库存能写入大数量。
