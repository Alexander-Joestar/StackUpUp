## 共同准则

以下为本清单所有任务共用的规则；各任务正文只写「本任务特有」的内容，不再逐条复述共同项。

- 容量底线是物品守恒：`stored + remainderCount == offered`。安全优先于扩大覆盖面。
- 容量站点只按写入源码分类：
    - **自洽**：真实写入在落盘前重新读取同一上限来源，或使用与广告值相同的底层来源。
    - **断链**：只改变广告值，真实写入不读取该值，也没有可靠 remainder。
    - **转发**：查询或写入转发给 delegate；包装器本身不是可安全抬高的独立容量来源。
- Forge `EntityEquipmentInvWrapper` 必须把 Forge wrapper 与 vanilla 实际存储/写入路径分开读源码后判定；不得写成“无余量必吞”（事实见
  P0 台账 a）。
- 第三方 jar 无源码时统一写 **无源码不可判定**，不得用类名、方法名、注释或经验补出结论。
- 不复活“写入后余量补偿方案”：审计只读、只记录、只报告，不回填、不重试、不补偿；`simulate` 与真实写入严格分开。
- 失败必须 fail-fast 并保留可定位证据；不使用反射绕过可达性问题，不留空 `catch`，不写占位实现。
- 每个任务的“写入范围”是后续执行边界；本阶段不触碰这些范围之外的文件。
- 事实源唯一：所有任务必须引用 P0 源码事实台账（下方），不得另造事实源；台账已锁定的事实（EntityEquipment 两路、
  ResourceLocation 多冒号、`resolveInventoryClampLimit` 调用面、第三方 artifact 缺失）只引用不复述。

> （ConservationAuditor/ConservationEvent/ConservationReportWriter）、JSONL 报告与 4 个审计测试已删除；
> AE2 热路径零逻辑化：mixin 不再包含任何注入（仅保留 config 保险丝），`insertItem` 原样执行，零分支零分配。
> "不吞"由原版/Forge remainder 契约结构性保证，运行期验证由
> 边界探针 `DevAutomationServerDriver#probeBoundaryLimit` 承担（insertItem (N) 全存 / 追加 insertItem (1) 被拒）。
> 本任务以下正文保留为历史规划，不再执行；T13 原依赖的 T12.5 门不再适用。

- 目标：在项目主动投喂物品的真实调用点外围建立默认关闭的守恒观察层，把静态无法穷举的第三方子类风险转成可定位的运行时机器报告。
- 依赖：P0；调用点盘点可与 T2a 并行。T12.5 只作为运行时证据回填门，不阻塞 T2b+T11 的静态目标表实现；T2 登记表的运行时回填必须完成并可追溯，才能进入
  T12.5 第三种最终状态。
- 证据增量：`IItemHandler.insertItem` 的 `simulate` 与 remainder 契约、AE2 投喂路径、`dev/`
  自动化探针路径、服务端自动验收矩阵；第三方实现无源码时按共同准则写 **无源码不可判定**。
- 交付物：T12.1/T12.3/T12.4/T12.5 的实现结果、关闭态开销门、真实投喂报告、T2 登记表和决策记录的运行时证据回填。
- 特有禁止项·验证·停止条件：
    - 禁止项：把审计改成“写入后余量补偿方案”；回填、重试、补偿或吞掉异常；将 `simulate=true` 当真实写入；默认开启；用类名代替行为证据。
    - 验证：增量命令 `./gradlew runServerAutoTestMatrix`；报告必须能区分模拟/真实调用并重现守恒与非守恒
      stub；全量回归门按共同准则统一执行。
    - 停止条件：任何调用点的 `simulate` 语义不清、真实写入无法包围、报告缺少 handler 类名或调用点、或审计器改变业务状态时，停止并不宣称守恒。
- 代理编排：先由静态分析代理穷举项目主动投喂点，再由运行时验证代理核对 `runServerAutoTestMatrix` 报告；禁止仅凭第三方类名作静态结论。
- 解锁项：T12.5 只解锁运行时证据回填门；T2b+T11 可在 T2a、T4a 完成后独立实现，T13 仅在 T3、T10、T11、T14.7 和 T12.5
  的最终状态均完成后解锁；T12.1–T12.4 的中间结果可用于早期发现断链，但不能替代最终报告。

### T12.1 可控真实投喂与 simulate 排除

- 目标：只包围项目自己发起的真实插入点，采集 `offered`、写入前状态、写入后状态与 remainder；显式区分 `simulate=true`
  与真实写入——模拟调用不产守恒事件、不改变状态、不执行第二次真实写入。`simulate` 排除是事件采集的固有语义，不再单独成关（原
  T12.2 并入本任务）。
- 依赖：P0；完成主动投喂点盘点，包括 AE2 限流器路径、`dev/` 探针路径和其他实际调用 `insertItem` 的项目代码；可与 T2a 并行。
- 证据增量：每个调用点的源码文件、方法签名、handler 来源和 `simulate` 实参；无法读取第三方实现时按共同准则记录无源码不可判定。
- 交付物：真实投喂点清单；统一事件入口；原始事件对象含调用点、handler 类名、slot、`offered`、`before`、`after`、remainder 与
  `simulate` 标志；`simulate=true` 的明确排除规则。
- 特有禁止项·验证·停止条件：
    - 禁止项：全局拦截、修改 handler 行为、把模拟调用改成真实调用、用额外写入来测量容量、反转或默认填充 `simulate`、提前加入回填或重试。
    - 验证：使用守恒 stub 和已知截断 stub 各执行 `simulate=false`，确认事件均来自一次真实写入且审计器不改变返回值或库存状态；同一守恒
      stub 的 `simulate=true` 不产守恒事件且不改变状态。
    - 停止条件：无法证明调用是项目主动投喂、无法取得真实写入前后状态、任一调用点 `simulate` 实参来源不明确、或 wrapper
      的返回值与实际调用契约不一致时停止该调用点接入。
- 代理编排：调用点审计拆 3 条并行 lane——AE2 路径 / `dev/` 探针路径 / 其余项目 `insertItem`
  调用方，各自盘点后汇总到统一事件入口；实现代理负责最小包围层，审查代理逐调用点核对参数流和返回值，不接受宽泛拦截。
- 解锁项：解锁 T12.3。

### T12.3 透明守恒

- 目标：只读计算 `(after - before) + remainderCount == offered`，不修正不平衡结果；任何不平衡都带上下文告警并保留现场证据。
- 依赖：T12.1；已定义真实写入事件和可重复的库存总量统计方式。
- 证据增量：handler 的 remainder 返回、目标容器状态统计、项目已有库存接口；若第三方内部重写物品而无法判定语义，报告数值事实并标无源码不可判定。
- 交付物：`storedDelta`、`remainderCount`、`offered`、`balanced` 字段；WARN 至少包含 handler 类名、slot、调用点、投喂量、实际落库量、余量。
- 特有禁止项·验证·停止条件：
    - 禁止项：写入后回填、重试、补偿、强制截断 remainder、把不平衡解释成某种第三方 bug 而不保留原始数值。
    - 验证：已知守恒 stub 不告警；`insertItem` 内将堆叠截到 64 且返回空余量的 stub 必须告警并包含类名；审计前后业务状态完全一致。
    - 停止条件：无法定义无副作用的 `before`/`after` 统计、公式被业务特殊语义改变、或告警丢失原始数值时停止。
- 代理编排：让测试代理先覆盖守恒和截断两类边界，再由代码审查代理确认审计没有写入路径。
- 解锁项：解锁 T12.4。

       T13。

- 证据增量：T12.1 的调用点清单、T12.3 的原始数值、`runServerAutoTestMatrix` 的运行输出；第三方无源码时按共同准则保留无源码不可判定。
- 交付物：版本化 JSONL 或等价机器格式，每条至少包含 `schemaVersion`、调用点、handler 类名、slot、`simulate`、`offered`、
  `before`、`after`、`storedDelta`、`remainderCount`、`balanced`；汇总报告列出所有不平衡类和调用点；T2 表逐条标注源码证据或运行时证据。
- 特有禁止项·验证·停止条件：
    - 禁止项：只写人工摘要、不写原始事件；丢弃平衡事件或模拟事件而不遵守 schema；用报告推断没有运行证据的源码行为；将告警自动变成补丁。
    - 验证：`./gradlew runServerAutoTestMatrix` 生成可解析报告；用守恒和截断 stub 校验 schema、数值和告警；报告中的每个不平衡条目都能回到调用点和
      handler 类名。
    - 停止条件：报告不可机器解析、缺少 `simulate` 或关键数值、同一次运行无法重现事件、或回填把无源码不可判定改成推测时停止。
- 代理编排：报告 schema 由数据审查代理先固定，再由实现代理接入；回填必须逐条引用原始事件。
- 解锁项：T12.5 只解锁运行时证据回填门；T2b+T11 的静态实现依赖 T2a、T4a，不受此门阻塞；只有第三种最终状态解锁 T13，且报告本身不能跳过

### T13.2 回扩路径准入规格

- 目标：为安全回扩建立窄范围、可验证的实现入口；每个场景明确是否回扩、需接管的真实写入面与停止条件；本小节只产出任务规格与决策记录，不修改生产代码。

  上限/remainder 的 Forge 源码位置），不以 GUI/广告值替代。
- EntityEquipment：分别列出 Forge wrapper 与 vanilla 存储写入证据——
    - Forge wrapper 写入证据（P0 事实 a）：`insertItem` 先以 `getStackLimit(slot, stack)` 计算可写入量（
      `EntityEquipmentInvWrapper.java:86-105`），helper 返回 `min(getSlotLimit(slot), stack.getMaxStackSize())`（`:168-171`
      ）；真实写入只在 `simulate == false` 时经 `setItemStackToSlot` 或现有堆叠的 `grow` 落库，达到上限时返回未接收部分（
      `:108-120`、`:122`）。
    - vanilla 存储写入证据：wrapper 落库调用 `EntityLivingBase#setItemStackToSlot`，该基类方法为抽象声明（
      `EntityLivingBase.java:1852-1856`），必须对目标具体实体子类另行闭合真实 setter 容量，不得由 wrapper 数值、槽位类型或类名推导任一子类。
    - 结论：只有 Forge wrapper 与 vanilla 子类两条写入路径都确认真实容量、上限计算与 remainder 闭合时，才生成手持槽窄任务；装甲槽保持不可堆叠（返回
      1 的语义不动）；否则决定不回扩并写理由。
- `InvWrapper` 包第三方 `IInventory`：只对 T12 观测到且有源码/可重复守恒证据的内层类生成 late mixin 任务，绝不重新 patch
  wrapper；没有证据的条目标为 **无源码不可判定** 并列出缺失 jar，决定不回扩。
- `InventoryLargeChest`：若回扩，必须让上、下两半共同成立，查询值取 `min(upper, lower)`，并配两半不一致测试；否则保持不 patch
  并记录理由。
- 验证：每条回扩规格拥有真实写入测试、remainder 守恒测试、目标表登记和 T12 报告关联；执行命令由后续独立实现任务按全量回归门明确列出，本任务当前不执行。
- 停止条件：只证明广告面、未证明真实写入面；EntityEquipment 缺少 Forge 与 vanilla
  写入证据仍分类；内层第三方缺源码仍想扩展；或大双箱两半来源不一致时停止回扩并保留现场。
- 解锁项：只解锁明确通过准入条件的独立回扩任务；未通过项保持安全收缩，不自动扩大覆盖面。

## 多代理并行执行与编排（执行方式，不新增任务）

本计划按「事实源唯一 + 并行 lane」执行，像多线程一样让独立证据链同时推进；所有 lane 的产出统一回到 P0 台账与 T2 登记表，
不各造事实源。P0 复核通过后按以下波次并发（每 lane 一个子代理，协调代理只合并产出、不代替各 lane 取证）：

- 子代理定义一律从 `docs/agent/子代理库.md` 选用（事实审查/写入路径复核/调用点盘点/Mixin
  inventory/字节码护栏/运行时验证/网络研究/文档收口/Terra 裁决/独立复核）。

- **波次 1（P0 后的独立枝，6 条并行）**：T12.1（3 条调用点 lane）、T2a、T4a、T7.0、T8.0（真实客户端，单 lane）、T9-R1（2 条 lane）。

- 每任务内部的「代理编排」给该任务 lane 划分；跨任务不变量（守恒、无源码不可判定、关闭态门）由共同准则统一裁决，不在各 lane
