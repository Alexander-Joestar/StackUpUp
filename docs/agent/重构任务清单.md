# 重构任务清单（后续实现总表）

本文件定义后续实现任务，并包含规划、证据审查和迁移准入任务。根级 `AGENTS.md` 是唯一规范来源；T2–T14
仍为规划，未表示生产完成；实现任务不改入口文档，文档收口只调整存续文档的链接、路径和状态，不重写已完成内容。工作副本中已有的未提交改动必须原样保留；禁止使用
`git restore`、`jj restore` 或任何覆盖式回退操作。

## 共同准则

- 容量底线是物品守恒：`stored + remainderCount == offered`。安全优先于扩大覆盖面。
- 容量站点只按写入源码分类：
    - **自洽**：真实写入在落盘前重新读取同一上限来源，或使用与广告值相同的底层来源。
    - **断链**：只改变广告值，真实写入不读取该值，也没有可靠 remainder。
    - **转发**：查询或写入转发给 delegate；包装器本身不是可安全抬高的独立容量来源。
- Forge `EntityEquipmentInvWrapper` 必须把 Forge wrapper 与 vanilla 实际存储/写入路径分开读源码后判定；不得把它写成“无余量必吞”。
- 第三方 jar 无源码时统一写 **无源码不可判定**，不得用类名、方法名、注释或经验补出结论。
- 不复活“写入后余量补偿方案”：审计只读、只记录、只报告，不回填、不重试、不补偿。
- 失败必须 fail-fast 并保留可定位证据；不使用反射绕过可达性问题，不留空 `catch`，不写占位实现。
- 每个任务的“写入范围”是后续执行边界；本阶段不触碰这些范围之外的文件。

## P0 工作副本保护与事实台账

- 依赖：无。

  `docs/agent/2026-04-18-hard-rules.md`、`docs/agent/compatibility-decision-record.md`、`build/rfg/minecraft-src/java/`
  和当前项目源码；台账必须记录以下事实：

       两条路径必须分别按源码判定，不能写成无余量必吞。
    2. 1.12.2 `ResourceLocation` 的 path 可含多个冒号；不能用冒号段数一概否定合法资源路径，也不能据此推断 meta。

    4. `resolveInventoryClampLimit` 仍有两个调用方；T4a 只处理 inventory-write 上下文通道，必须保留该 resolver 及其两个调用方。
    5. T12 必须区分 `simulate` 与真实写入，排除模拟调用，并产出机器可读报告。
- 写入范围：本文件的事实台账、任务依赖和证据约束；后续任务只写各自列明的仓库相对路径。不得为了建立台账覆盖用户已有改动。
- 禁止项：把未经证据核实的判断直接当结论；复制任务外部状态或未经验证的第三方结论；使用回退命令清理工作副本；把“无源码不可判定”改写成猜测。
- 交付物：带源码位置的事实台账；三处纠正事实逐条可追溯；`resolveInventoryClampLimit` 的两个调用方清单；工作副本保护记录。

  `jj diff` 核对本任务变更范围，不撤销其他改动。
- 失败停止条件：源码与台账冲突、两个调用方无法逐一定位、真实 F3+T 无法观察、或发现工作副本有非本任务覆盖操作时，停止后续任务并保留现场，不作推断或回退。
- 模型建议：采用证据优先的只读审查；执行阶段使用熟悉 Forge 1.12.2、Java 8、Kotlin 与 Mixin 的实现代理，所有判断都附可复核源码位置。
- 解锁项：解锁 T12.1、T2a、T4a、T7.0、T8.0、T9-R1；其他任务必须引用本台账，不得另造事实源。

## T12 运行时守恒审计（总任务）

- 目标：在项目主动投喂物品的真实调用点外围建立默认关闭的守恒观察层，把静态无法穷举的第三方子类风险转成可定位的运行时机器报告。
- 依赖：P0；调用点盘点可与 T2a 并行。T12.5 只作为运行时证据回填门，不阻塞 T2b+T11 的静态目标表实现；T2 登记表的运行时回填必须完成并可追溯，才能进入
  T12.5 第三种最终状态。
- 证据：`IItemHandler.insertItem` 的 `simulate` 与 remainder 契约、AE2 投喂路径、`dev/`
  自动化探针路径、服务端自动验收矩阵；第三方实现无源码时只记为无源码不可判定。
- 写入范围：审计器、项目主动投喂调用点、`dev/` 自动化报告、对应长期测试和事实回填；不得全局改写所有第三方 handler。
- 禁止项：把审计改成“写入后余量补偿方案”；回填、重试、补偿或吞掉异常；将 `simulate=true` 当真实写入；默认开启；用类名代替行为证据。
- 交付物：T12.1–T12.5 的实现任务结果、关闭态开销门、真实投喂报告、T2 登记表和决策记录的运行时证据回填。
- 验证：`.\gradlew.bat test`、`.\gradlew.bat runServerAutoTestMatrix`；报告必须能区分模拟/真实调用并重现守恒与非守恒 stub。
- 失败停止条件：任何调用点的 `simulate` 语义不清、真实写入无法包围、报告缺少 handler 类名或调用点、或审计器改变业务状态时，停止并不宣称守恒。
- 模型建议：先由静态分析代理穷举项目主动投喂点，再由运行时验证代理核对 `runServerAutoTestMatrix` 报告；禁止仅凭第三方类名作静态结论。
- 解锁项：T12.5 只解锁运行时证据回填门；T2b+T11 可在 T2a、T4a 完成后独立实现，T13.1 仅在 T3、T10、T11 和 T12.5
  的最终状态均完成后解锁；T12.1–T12.4 的中间结果可用于早期发现断链，但不能替代最终报告。

### T12.1 可控真实投喂

- 目标：只包围项目自己发起的真实插入点，采集 `offered`、写入前状态、写入后状态与 remainder，为后续守恒计算提供原始事件。
- 依赖：P0；完成主动投喂点盘点，包括 AE2 限流器路径、`dev/` 探针路径和其他实际调用 `insertItem` 的项目代码。
- 证据：每个调用点的源码文件、方法签名、handler 来源和 `simulate` 参数；无法读取第三方实现时记录无源码不可判定。
- 写入范围：审计器、已列出的项目主动投喂点、对应测试；不得把审计注入未知第三方的所有调用面。
- 禁止项：全局拦截、修改 handler 行为、把模拟调用改成真实调用、用额外写入来测量容量、提前加入回填或重试。
- 交付物：真实投喂点清单；统一事件入口；包含调用点、handler 类名、slot、`offered`、`before`、`after`、remainder 的原始事件对象。
- 验证：使用守恒 stub 和已知截断 stub 各执行 `simulate=false`，确认事件均来自一次真实写入且审计器不改变返回值或库存状态。
- 失败停止条件：无法证明调用是项目主动投喂、无法取得真实写入前后状态、或 wrapper 的返回值与实际调用契约不一致时停止该调用点接入。
- 模型建议：实现代理负责最小包围层；审查代理逐调用点核对参数流和返回值，不接受宽泛拦截。
- 解锁项：解锁 T12.2。

### T12.2 simulate 排除

- 目标：显式区分 `simulate=true` 与真实写入；模拟调用完全排除出守恒统计，不执行第二次真实写入，也不产生损失告警。
- 依赖：T12.1；Forge `IItemHandler` 接口及项目各调用点的参数语义已确认。
- 证据：`insertItem(..., simulate)` 的接口定义、每个主动投喂调用点的实参、handler stub 对模拟调用的行为。
- 写入范围：统一入口的 `simulate` 分支、调用点适配、模拟/真实双路径测试。
- 禁止项：反转或默认填充 `simulate`；将模拟结果当落库量；为审计而把模拟升级成真实写入；通过反射读取隐藏状态。
- 交付物：事件中的 `simulate` 标志和真实写入判定；`simulate=true` 的明确排除规则；模拟不改变状态、真实才进入 T12.3 的测试。
- 验证：同一守恒 stub 分别执行模拟和真实插入，模拟不产守恒事件且不改变状态，真实插入产生完整事件；对实际调用点逐一检查没有遗漏或反接。
- 失败停止条件：任一调用点的 flag 来源不明确、模拟调用可能改变状态而无法检测、或审计仍对模拟调用发出损失告警时停止。
- 模型建议：使用接口契约审查与行为测试组合；不以调用方命名推断 `simulate` 语义。
- 解锁项：解锁 T12.3，并为 T12.4 的关闭态门提供完整分支边界。

### T12.3 透明守恒

- 目标：只读计算 `(after - before) + remainderCount == offered`，不修正不平衡结果；任何不平衡都带上下文告警并保留现场证据。
- 依赖：T12.2；已定义真实写入事件和可重复的库存总量统计方式。
- 证据：handler 的 remainder 返回、目标容器状态统计、项目已有库存接口；若第三方内部重写物品而无法判定语义，报告数值事实并标无源码不可判定。
- 写入范围：守恒计算、结构化告警、测试 stub；不写入业务库存、不改变 remainder。
- 禁止项：写入后回填、重试、补偿、强制截断 remainder、把不平衡解释成某种第三方 bug 而不保留原始数值。
- 交付物：`storedDelta`、`remainderCount`、`offered`、`balanced` 字段；WARN 至少包含 handler 类名、slot、调用点、投喂量、实际落库量、余量。
- 验证：已知守恒 stub 不告警；`insertItem` 内将堆叠截到 64 且返回空余量的 stub 必须告警并包含类名；审计前后业务状态完全一致。
- 失败停止条件：无法定义无副作用的 `before`/`after` 统计、公式被业务特殊语义改变、或告警丢失原始数值时停止。
- 模型建议：让测试代理先覆盖守恒和截断两类边界，再由代码审查代理确认审计没有写入路径。
- 解锁项：解锁 T12.4。

       T13.1。
- 依赖：T12.3、T12.4；真实调用点和关闭态门均已验证。
- 证据：T12.1 的调用点清单、T12.3 的原始数值、`runServerAutoTestMatrix` 的运行输出；第三方无源码时保留无源码不可判定。

- 禁止项：只写人工摘要、不写原始事件；丢弃平衡事件或模拟事件而不遵守 schema；用报告推断没有运行证据的源码行为；将告警自动变成补丁。
- 交付物：版本化 JSONL 或等价机器格式，每条至少包含 `schemaVersion`、调用点、handler 类名、slot、`simulate`、`offered`、
  `before`、`after`、`storedDelta`、`remainderCount`、`balanced`；汇总报告列出所有不平衡类和调用点；T2 表逐条标注源码证据或运行时证据。

  handler 类名。
- 失败停止条件：报告不可机器解析、缺少 `simulate` 或关键数值、同一次运行无法重现事件、或回填把无源码不可判定改成推测时停止。
- 模型建议：报告 schema 由数据审查代理先固定，再由实现代理接入；回填必须逐条引用原始事件。
- 解锁项：T12.5 只解锁运行时证据回填门；T2b+T11 的静态实现依赖 T2a、T4a，不受此门阻塞；只有第三种最终状态解锁 T13.1，且报告本身不能跳过
  T2a 的准入规则。
