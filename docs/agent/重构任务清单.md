## 待办要点

- **容量与规则基线（P0、T2–T7）**：广告容量不得大于真实写入容量；真实写入满足 `storedDelta + remainderCount == offered`；`simulate` 与真实写入分开；规则 reload 只发布完整不可变快照。第三方 jar 无源码时标「无源码不可判定」，不按类名扩容。
- **T8 本地化**：T8.0 只有真实客户端 F3+T 前后观察才算收口，静态 `LanguageMap.replaceWith` 只能辅助验证；T8.1 的不可变自有译表不等于客户端全局重载桥接，T8.2 缺真实基线时别急着加 listener 或改聊天语义。
- **T9/T14 版本与 Mixin**：当前事实 MixinBooter **11.17** + CleanMix **0.7.2** + `IMixinConnector`，10.7 与旧 loader 只作历史比较；Mixin 优先，只有目标、签名和生命周期证据明确且 Mixin 不足时才用窄范围 ASM，编译通过不能替代运行时和字节码证据。
- **T12/T13**：T12 方案 A 已归档，「不吞」只由真实 `remainder` 契约和边界探针验证，禁止恢复写入后重算、回填、重试或补偿；T13 先闭合收缩矩阵再写窄范围回扩规格，至少覆盖装甲/手持槽、`InvWrapper` 包第三方 `IInventory`、`InventoryLargeChest`，每行关联源码或目标表，第三方无源码保持不可判定，不得把安全收缩写成功能修复。
- **T15/T16**：T15 的「结构已落地」和「验证已通过」分别记，别用目录或编译存在替代全量构建/产物对比；T16 还没开始，别把 wrapper、依赖、发布配置或 MixinBooter 版本改动塞进别的任务的结论里。
